# 鉴权与清理可靠性修复

## 本次修复

1. 撤销名单与待移除的 WireGuard 公钥一起写入 membership.json；删除对端失败会返回错误、停止后台并尝试关闭整个隧道。待清理公钥在下次启动、允许缓存连接前重试。启动时还会审计 NAS 残留的 WireGuard 对端，只保留缓存中经过验证且仍获批准的公钥。若底层系统拒绝所有清理命令，程序会报错，不能保证内核通道已经删除。
2. 批准、发送失败回滚、撤销与待清理任务处理共用同一事务锁，避免并发覆盖成员名单。
3. 断开清理结果写入 shutdown.json；Windows 在后台与控制接口退出后检查结果。异常退出和清理失败均显示“清理未完成”，提供提权“重试清理”入口。命令行也可使用 `sudo nknguard --config <path> cleanup`，该命令拒绝清理正在运行的实例。
4. NAS 面板在 NKN 初始化前启动，可以查看状态、日志和处理授权撤销；新配对在 NKN 就绪前返回 503，并显示明确说明。面板状态区分等待信标与 NAS 就绪。
5. 状态目录和控制 socket 均使用操作系统独占文件锁。重复启动会失败，不会替换活动实例的控制 socket。关闭句柄或进程退出后由系统释放锁；锁文件保留以避免 inode 替换竞态。

Android 测试版版本更新为 0.2.2（versionCode 4）。网络协议保持 v1；membership.json 新增可选的 pending_wireguard_removals 字段。

## 回归验证

- 并发撤销 24 个成员，磁盘名单不丢失更新。
- 批准发送阻塞及失败回滚与另一个设备撤销交错，不恢复已撤销成员。
- 删除公钥失败、关闭整个隧道也失败时，不返回撤销成功；待清理任务重启后仍保留并可重试。
- 晚到的对端安装在撤销后完成，也走同样的安全清理逻辑。
- NAS 残留对端审计保留获批准的已验证公钥，移除未知公钥。
- NKN 工厂阻塞时，真实本地 HTTP 面板仍能登录查询状态，配对返回 503。
- 独占锁拒绝重复获取，释放后可重新获取；重复 API 启动不影响现有 socket。
- 清理失败、未完成及成功三种持久化状态得到区分，重开 Windows 界面仍显示失败。
- Linux 查询接口失败不能等同于接口不存在；Windows 卸载命令成功后还须通过服务管理器确认服务已不存在。

## 发布边界

本次没有更新在用 NAS 服务或重新生成 FPK。实机安装、升级、卸载、真实 UAC 操作和公网连接仍需实际设备验收。
Windows 代码签名、Android 固定 release 签名尚未配置；CI APK 仍为 debug 包，不能保证与其他 CI 运行产物覆盖升级。需使用维护者持有的签名材料配置正式发布，不能把代码签名视为火绒检测一定消失的保证。
