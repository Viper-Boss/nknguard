# Android 局域网地址与 NKN 启动检查

## 观察与边界

在同网段 Wi-Fi 测试中，手机可以通过 NKN 中继完成 WireGuard 握手，但新发布的连接记录缺少局域网 host 候选，只包含公网映射。需要修复物理网络地址采集，并在实际手机上确认直连握手。

移动网络下还观察到 NKN 注册完成后消息检查失败和中继拨号超时。自发自收成功只能验证该身份的消息收发，不能单独证明对端可达，也不能定位到某个运营商或节点。

## 0.2.8 修复

每次连接前重新报告当前物理网络，避免沿用核心启动时的网络信息。网络回调如果给出 VPN 网络，改为选取非 VPN 网络；缺少有效默认网络时优先选择验证过的 Wi-Fi。除 LinkProperties 地址外，在该网络上绑定临时 UDP socket，以 connect 选出的源地址补充 IPv4/IPv6 host 候选；不发送 UDP 数据，不依赖 DNS。没有可用网络时报告空地址，清除旧网络信息。

NKN 的 SDK OnConnect 不再直接计作启动成功：在原有 30 秒总预算内进行最长 12 秒的随机加密自发自收检查；失败关闭这次客户端并由已有启动重试重新创建。验证要求正确来源、加密以及当前随机内容，其他消息不能授予连接状态。新客户端验证不会关闭 WireGuard 接口或改变虚拟 IP。

SDK 标准日志进入现有脱敏内存环，补齐此前诊断没有收录的底层网络错误。诊断增加实际物理地址、NKN 节点地址，以及探测的发送错误或接收超时原因。不增加持续磁盘日志，不收集 SSID。

## 验证

移动核心、NKN 客户端和信令健康检查测试已在 ARM64 测试主机通过。临时 NKN 身份的实际加密自发自收检查通过。

新版本需要确认：手机报告的物理地址正确，NAS 收到同网段 host 候选，并通过实际 WireGuard 收包或新握手验证直连。不能仅凭候选地址存在宣称已连通。

移动网络具体失败节点与底层错误仍需新版诊断；不能把 Wi-Fi 中继成功等同于移动网络恢复。当前内核 WireGuard 仍只有一个 peer 端点，中继传输期间的直连探测不保证完全无中断。
