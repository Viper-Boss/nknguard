# fnOS ARM64 package test, 2026-09-27

Tested on an ARM64 fnOS NAS with `fnpack` 1.2.0, `appcenter-cli` 1.0.1,
`wg`, and `ip`. The package was built by `fnpack` and copied back locally as
`dist/nknguard-fnos-arm64.fpk`.

SHA-256: `40fff353a458afd08f75ee32838827e28991e26cd79f5212692a9184a1c8db4a`

## Results

| Check | Result |
| --- | --- |
| ARM64 Go binary | Ran; reported NKN and DHT features enabled |
| `fnpack build` | Passed; FPK contains manifest, lifecycle hooks, icons, and binary payload |
| App Center install | Blocked by NAS volume configuration: default volume `0`; volume `1` and `2` both reported unavailable |
| Isolated install hooks | Passed; first-run config, identity, and dashboard key created in private app-like directories |
| Service start | Passed; `nkg0` came up and the daemon connected to NKN |
| Local dashboard | Returned HTTP 401 without credentials, as expected |
| Isolated stop and uninstall hooks | Passed; daemon stopped and `nkg0` disappeared |
| Residual check | No NKNGuard process, `nkg0`, App Center record, or private test state remained |

The DHT initially had no known peer and logged failed peer publication. No
Windows-to-NAS WireGuard handshake or NKN relay transfer was tested in this
run. Because App Center had no available installation volume, a full App
Center install/uninstall cycle could not be verified. The isolated hook test
does not prove that fnOS will remove all app directories during a real
uninstall.

To complete the full package test, configure an App Center installation
volume in fnOS, then install the FPK on that volume and uninstall it from
App Center. Verify `appcenter-cli check nknguard`, `/sys/class/net/nkg0`,
the process list, and the app configuration/data directories after removal.
