# DHT 与 NKN 协同

## 本次补充

1. 私有 libp2p Kademlia 同时监听 IPv4 / IPv6 TCP，支持 Android 提供的底层地址。
2. DHT 与缓存链路探测先启动，不等待 NKN 连接完成。已通过签名、成员证明与批准名单验证的设备记录可用于重新连接；首次配对仍通过 NKN。
3. DHT 中已建立的连接可以传送有签名的控制信封，包括 ICE 协商与设备信息；失败时回退到 NKN。WireGuard 数据不会作为 DHT 消息发送。

## 安全边界

DHT 是本项目的私有协议，不加入公共 IPFS DHT。设备 ID 与 libp2p 身份的绑定来自已验证的记录。
收到的信封仍交给同一个控制器按顺序验证签名、网络、时效、重放与设备授权。撤销后不能通过 DHT 恢复授权。
每台最多 512 个身份绑定，信封上限 64 KiB，最多 16 个入站信令流；连接和读写均有超时。

## 可达性限制

DHT 需要至少一个可达的引导或缓存对端。没有可达地址、路由表为空或双方都在无法打洞的 NAT 后面时，它不会凭空形成连接，也不会代替中继。
旧客户端没有 DHT 信令能力时继续使用 NKN。双方升级后可使用该通道；公网 IPv6 是否可达需以实际探测为准。

## 动态端口映射

NAS 端 `nat.port_mapping: true` 默认尝试 UPnP / NAT-PMP。它映射实际分配的随机 WireGuard UDP 端口，端口变化后更新映射，停止时请求删除；DHT 的 TCP 映射由 libp2p 管理。
失败不会阻塞连接。映射仍不能穿过路由器上游的 CGNAT；异常断电后的租约清理由路由器实现决定。
不支持映射时保留 ICE 与 NKN 回退。可在配置中设为 `false` 关闭主动映射。

## 验证

自动回归使用两个真实 libp2p DHT 与 ICE UDP 对端，在不接入 NKN 的条件下建立经过验证的直连，并检查撤销。
这证明通道和协议工作，不能作为所有运营商网络可达的保证。
