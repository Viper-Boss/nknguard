# 连接可靠性修复说明

基于 Claude 的 `e5c12b6`，修复 2026-10-07 审查指出的五项问题。

## 变更

1. **Windows 启动期间取消/退出。** 用 `ShellExecuteExW` 保留提权后台的进程句柄，等待 UAC 启动结果，
   通过提前启动的本地控制接口取消初始化。界面等待后台退出及控制接口关闭后才报告已断开，退出失败保留窗口。
   控制接口持续到 WireGuard 清理结束，连接中提供取消按钮，退出清理在后台执行。
2. **Android 密钥保存确认。** `secrets` 事件带递增序号；Kotlin 完成加密、文件同步和替换后回复 `secrets_ack`。
   Go 收到成功 ACK 才提交内存密钥和配对成功状态；失败或超时返回错误。串行命令工作队列与 ACK 读取分开，
   避免等待保存时阻塞 IPC。该调整只影响 APK 内部接口，不改 NAS 的网络协议。
3. **缓存直连与 NKN 上线并行。** 先验证缓存记录及会员/批准状态，恢复与公钥绑定且不超过七天的直连提示。
   缓存阶段只安装已授权对端、发送 WireGuard 探测并观察真实握手；不发布旧记录、不授权陌生设备。
   NKN 初始化失败独立重试；上线后停止缓存阶段，接入完整控制器，并立即请求新的签名记录。
4. **Android 断开兜底。** IPC 断开超时会终止 Go 核心，必要时强制结束，并等待退出确认，使其持有的 TUN fd 被关闭。
   清理失败保留错误状态，旧进程退出不会影响新进程。网络回调在停止期间不再入队。
5. **Android 主线程清理。** 删除服务 `onDestroy()` 的最长十五秒等待，清理留给后台执行。

## 新增回归测试

- 启动时 API 暂不可用不能认定后台已退出；收到停止 ACK 后仍等待清理；后台卡住时返回错误。
- NKN 初始化期间取消和取消后才返回的迟到 plane 关闭。
- 初始化密钥保存失败不生成已提交身份；入网密钥保存失败不报告已配对；失败不替换旧密钥。
- 没有 signaling 时缓存端点也能被探测；模拟数据面没有回应时不显示成功，有握手后才显示直连。
- 错误设备、公钥及过期缓存提示被拒绝。
- Android 会话在 NKN 仍阻塞时已经设置缓存端点，且可断开结束会话。

## 验收范围

由仓库 GitHub Actions 验证；以本次提交对应的 Actions 结果为准。

尚需实际设备测试：真实 UAC 取消、WireGuard 服务与路由清理、手机 Keystore 故障/空间不足、蜂窝与 Wi-Fi 切换、
锁屏、NKN 公网中继、NAS 撤销、APK 升级与卸载。此次没有更新 NAS 的在用服务或 FPK 安装。

正式 Android 发布仍需要固定、保密的 release 签名密钥；CI debug 签名不适合持续升级。Windows 签名也需要另行配置。
