# 直连切换和网络动画修复

从 NAS 内存日志观察到：一次直连尝试尚未验证成功，轮询便把刚配置的公网端点
与之前中继的握手时间组合，误判为直连并关闭中继；随后同一次尝试报告失败。
另一处竞争是 NKN 会话晚到，覆盖刚建立的直连端点。

- 直连探测期间不切换路径、不关闭中继；失败恢复中继端点后才释放探测标记。
- 直连探测与中继接入串行修改端点；迟到的中继不能覆盖仍在收包的已验证直连。
- 回到直连必须经过完整观察时间，不能通过暂时没有中继端点的状态绕过。
- 每个候选地址单独建立握手/收包基线；公网映射优先于 Docker 等虚拟接口，
  同一局域网候选优先。去掉缺少接口作用域的 IPv6 链路本地地址。
- STUN 暂时失败保留尚未到期的公网映射；真实网络切换时清除旧映射。
- Android 按底层网络标识和地址集合判断变化，重复通知、地址顺序变化不重建隧道。
- 网络卡片补连接弧线、流光和多跳节点效果，保留隐藏暂停、20 帧上限、减少动画设置。
  蓝色发现连线明确标为示意，不能把示意图当作真实节点数量或流量。

NAS ARM64 实机执行 mesh、mobile、nat 测试通过。完整编译、竞态测试和 Android
构建由 GitHub Actions 再验证。真实蜂窝网络端到端稳定性仍需要新客户端实测；
部分 NAT 类型无法穿透时，正确行为是保留中继，不保证所有网络都能直连。
