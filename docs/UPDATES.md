# 安装包与升级

## 下载位置

安装包在 GitHub 仓库右侧的 **Releases**；Packages 用于容器等包分发，不是 APK / FPK 下载区。安卓、Windows 安装器、Windows 便携包、飞牛 x86_64 与 ARM64 FPK 分别提供。

Android 维护者发布包保持原有签名，版本号递增，可覆盖升级原来的 `io.github.viperboss.nknguard.debug` 客户端。不要用 Actions 临时签名调试包覆盖安装。

## NAS

1. 打开后台 **系统更新 → 检查更新**。
2. 在发布页下载与处理器、安装方式相符的 `NKNGuard-NAS-Update-…zip`。
   - 数据盘上的独立服务使用 `linux-amd64` 或 `linux-arm64`。
   - 应用中心 FPK 安装使用 `fnos-amd64` 或 `fnos-arm64`。
3. 选择更新包，点击 **上传并更新**。仅在你确认后开始；安装时连接会短暂断开。
4. 更新完成后刷新。原有管理密码、设备密钥、配对、虚拟 IP 与配置保持不变。

更新包包含发布目录、Ed25519 签名及对应程序 / FPK，上传后验证签名、版本、大小、SHA256 和处理器架构。拒绝旧版本、损坏包、其他架构、路径穿越和额外文件。独立服务使用单独的更新进程，启动验证失败时恢复旧程序；成功后仅保留一份 `.previous` 程序作为备份。FPK 交给飞牛应用中心升级，应用中心还可直接导入 FPK。

NAS 更新只支持现有 `nknguard.service` 独立服务与标准应用中心安装，其他自行定制的服务请使用自己的安装管理器。首次从没有“系统更新”按钮的旧版升级，需要先通过原部署方式更新一次程序。

检查更新仅访问 GitHub，不定时下载、不持续写硬盘。只有手动升级才暂存更新包并写入少量任务状态；临时文件在任务结束时清理。系统更新不创建新身份。

## Android

在 **应用更新** 点击 **检查更新**，发现新版后选择下载；也可选择本地 APK。安装前核对版本、包名与当前签名，在线下载还核对已签名发布目录中的摘要。首次安装更新时，Android 会要求允许 NKNGuard 安装应用，再点击 **安装已下载更新**。安装本身由系统窗口确认。

## Windows

在 **应用更新 → 检查更新** 查看新版本并打开发布页，下载 Windows 安装器。在托盘菜单中退出 NKNGuard 后启动安装器，可覆盖升级。配对状态保存在用户资料目录，不会因覆盖安装被重建。Windows 的 VPN 仍需官方 WireGuard for Windows。

## 维护者发布流程

推送 `v…` 标签或 `release/v…` 分支后，工作流构建所有安装包并创建草稿。维护者在持有原 APK 签名和发布签名密钥的设备上运行：

```sh
python3 packaging/finalize-release.py v0.2.15-preview.1 --work /private/release-stage
```

脚本重签 APK、生成已签名目录和 NAS 更新包，再上传并公开发布。密钥和 GitHub 登录留在维护者设备，不进仓库、不进入普通 CI；更新器内只有公开验证密钥。

FPK 需要飞牛应用中心支持的数据卷。请保留已有数据，不要为了安装格式化大盘。构建校验和独立服务测试不能代替所有机型的应用中心实机验收。
